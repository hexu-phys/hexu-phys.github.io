Research question

Analyses drift. A figure produced six months ago is often impossible to regenerate exactly, because the steps lived in shell history, notebook cells, and manual edits. This project asked a practical question: what is the smallest amount of structure that makes an analysis for [Method] re-runnable by someone who did not write it, without slowing down the person who did?

Methods

  • Decomposed the existing analysis into four stages: ingest, validate, derive, render.
  • Defined an explicit data contract for each stage, with schema checks on inputs and outputs.
  • Moved every tunable choice into a single configuration file, including fit windows and plot ranges.
  • Added a regression test that regenerates a figure from a small archived dataset and compares against a stored reference.
  • Wrote handover documentation and walked two group members through a full reproduction.

Tools

  • [Python] for the pipeline; [pandas] for tabular stages.
  • [Make] as the single entry point, so each stage can be re-run in isolation.
  • [Matplotlib] for all figures, with a shared style file.
  • [Git] with one branch per analysis revision; [Environment file] to pin versions.

My contribution

  • Designed the four-stage decomposition and the configuration schema.
  • Implemented the pipeline and the schema validation, including clear failure messages.
  • Produced the pipeline diagram and the written technical note.
  • Trained other group members on the workflow and collected their feedback into the documentation.

Results (high level)

The reorganized pipeline regenerates every figure in the analysis from raw output, with no manual intermediate steps. Reproduction time for a new group member dropped from roughly a week of informal guidance to a single documented session, and the regression test now catches silent changes in derived quantities.
